# Kep 设备通信平台 - 代码分析文档

## 一、项目概述

Kep 是一个基于自定义二进制协议的 TCP 设备通信平台，采用客户端-服务端架构，支持 TLS 加密通信、身份认证、心跳保活、文件分片传输等功能。主要用于智能电表等 IoT 设备与服务端之间的数据交互。

### 技术栈
- **.NET 9.0**
- **Windows Forms**（UI 层）
- **TCP + TLS 1.2/1.3**（通信层）
- **自定义二进制帧协议**（应用层）

### 解决方案结构

| 项目 | 类型 | 说明 |
|------|------|------|
| `ZepCommon` | 类库 | 公共基础库：协议常量、数据帧、CRC校验、环形缓冲区、分片文件重组 |
| `KepServerCore` | 类库 | 服务端核心：TCP监听、TLS握手、会话管理、消息路由 |
| `KepClientCore` | 类库 | 客户端核心：TCP连接、TLS握手、版本协商、认证、心跳、文件传输 |
| `KepServerHub` | WinForms | 服务端 UI：客户端管理、日志、文件下发、请求回复 |
| `KepDevSmartMeter` | WinForms | 客户端 UI：连接管理、日志、文件上传 |

## 三、通信协议详细设计

### 3.1 连接建立流程（两阶段）

```
阶段一：纯文本协商（TLS 握手完成后）
═══════════════════════════════════════
  服务端 ──► 下发版本列表（纯文本，以 \r\n\r\n 结尾）
             例: "v1.0.0\r\nv1.1.0\r\nv2.0.0\r\n\r\n"

  客户端 ──► 选择版本（纯文本，以 \r\n 结尾）
             例: "v2.0.0\r\n"

阶段二：帧协议通信
═══════════════════════════════════════
  客户端 ──► 发送认证帧 (AuthRequest, Fn=0x0003)
  服务端 ──► 返回认证结果帧 (AuthResponse, Fn=0x0004)
  
  认证成功后进入主消息循环...
```

### 3.2 帧格式定义

```
┌──────────┬──────────┬──────────┬──────────┬──────────────┬──────────┐
│ 帧头(2B) │ 功能码(2B)│ 会话ID(4B)│ 数据长度(4B)│  数据域(NB)  │ CRC32(4B)│
│ 0xA55A   │FuncCode │   Id     │  Length  │    Data      │ Verify   │
└──────────┴──────────┴──────────┴──────────┴──────────────┴──────────┘
  小端序       小端序      小端序      小端序                   小端序
```

- **帧头**：固定 `0xA55A`，用于帧边界识别
- **功能码**：标识消息类型（见 3.3 功能码表）
- **会话 ID**：请求-响应配对标识，自增生成
- **数据长度**：数据域的字节长度
- **数据域**：实际载荷（UTF-8 文本或二进制数据）
- **CRC32**：仅对数据域计算校验，多项式 `0xEDB88320`

**帧总长度** = 2 + 2 + 4 + 4 + N + 4 = 16 + N 字节

### 3.3 功能码定义

| 功能码 | 常量名 | 方向 | 说明 |
|--------|--------|------|------|
| `0x0001` | `VersionList` | S→C | 服务器下发版本列表 |
| `0x0002` | `VersionSelect` | C→S | 客户端选择版本 |
| `0x0003` | `AuthRequest` | C→S | 身份认证请求 |
| `0x0004` | `AuthResponse` | S→C | 身份认证响应 |
| `0x0005` | `HeartbeatPing` | C→S | 心跳请求 |
| `0x0006` | `HeartbeatPong` | S→C | 心跳响应 |
| `0x0007` | `TimeSyncRequest` | C→S | 对时请求 |
| `0x0008` | `TimeSyncResponse` | S→C | 对时响应 |
| `0x0009` | `TempUpload` | C→S | 温度上报 |
| `0x000A` | `TempAck` | S→C | 温度上报确认 |
| `0x000B` | `ParamRequest` | S→C | 参数下发请求（需等待回复） |
| `0x000C` | `ParamResponse` | C→S | 参数下发回复（确认收到） |
| `0x000D` | `ClientRequest` | C→S | 客户端上报请求（需等待回复） |
| `0x000E` | `ClientResponse` | S→C | 客户端上报回复（确认收到） |
| `0x000F` | `FileDownload` | S→C | 文件下发（分片） |
| `0x0010` | `FileDownloadAck` | C→S | 文件下发确认 |
| `0x0011` | `FileUpload` | C→S | 文件上传（分片） |
| `0x0012` | `FileUploadAck` | S→C | 文件上传确认 |

### 3.4 请求-响应模式

系统支持两种请求-响应模式：

**模式 A：服务端下发参数，等待客户端回复**
```
服务端 ──► ParamRequest (Id=N, Data=参数内容)
客户端 ──► ParamResponse (Id=N, Data=ACK:参数内容)
```
- 服务端通过 `KepConversation.SendCommandAsync()` 发送并阻塞等待
- 默认超时 10 秒
- 客户端 `ReadLoopAsync` 收到 `ParamRequest` 后自动回复 `ACK:{参数}`

**模式 B：客户端上报请求，等待服务端手动回复**
```
客户端 ──► ClientRequest (Id=N, Data=请求数据)
服务端 ──► ClientResponse (Id=N, Data=回复内容)
```
- 客户端通过 `KepClient.SendRequestAndWaitAsync()` 发送并阻塞等待
- 默认超时 10 秒
- 服务端收到后存入待回复列表，由 UI 手动回复

### 4.2 DataPack - 数据帧封装

**文件**: `ZepCommon/DataPack.cs`

#### 数据结构

| 属性 | 类型 | 说明 |
|------|------|------|
| `Magic` | `ushort` | 帧头魔数，默认 `0xA55A` |
| `FunctionCode` | `ushort` | 功能码 |
| `Id` | `uint` | 会话 ID（请求/响应对应） |
| `Length` | `int` | 数据域长度（自动计算） |
| `Data` | `byte[]` | 数据域 |
| `Verify` | `uint` | CRC32 校验码 |

#### 核心方法

| 方法 | 说明 |
|------|------|
| `Serialize(DataPack)` | 将帧序列化为字节数组（帧头+功能码+ID+长度+数据+CRC32） |
| `Deserialize(RingBuffer)` | 从环形缓冲区反序列化一帧（含帧头校验、CRC校验） |
| `SendAsync(Stream, DataPack, SemaphoreSlim, CT)` | 异步发送帧（带写锁保护，线程安全） |
| `ReceiveAsync(Stream, RingBuffer, CT)` | 异步接收帧（自动处理粘包/半包） |
| `GetStringData()` | 获取数据域的 UTF-8 字符串 |

#### 序列化流程

```
Serialize():
  [帧头 0xA55A (2B, LE)]
  [功能码 (2B, LE)]
  [会话ID (4B, LE)]
  [数据长度 (4B, LE)]
  [数据域 (NB)]
  [CRC32 (4B, LE)]  ← 仅对数据域计算

ReceiveAsync():
  1. EnsureAsync() 确保读够 12 字节帧头
  2. Peek() 偷看帧头获取数据域长度 N
  3. EnsureAsync() 确保读够 12 + N + 4 字节完整帧
  4. Deserialize() 反序列化（含 CRC 校验）
```

### 4.3 CrcCalculator - CRC32 计算器

**文件**: `ZepCommon/CrcCalculator.cs`

- 使用标准 CRC32 算法，多项式 `0xEDB88320`（反转多项式）
- 初始化时预计算 256 项查找表
- 初始值 `0xFFFFFFFF`，最终异或 `0xFFFFFFFF`
- 仅对数据域（Data）计算校验，不包含帧头

### 4.4 RingBuffer - 环形缓冲区

**文件**: `ZepCommon/RingBuffer.cs`

**用途**: 从 TCP 流式读取中拼装完整帧，解决 TCP 粘包/半包问题。

#### 核心设计

```
容量: 8192 字节（默认）
保留 1 字节哨兵位，区分空/满状态
支持跨边界读取（数据在缓冲区首尾回绕）
```

#### 关键方法

| 方法 | 说明 |
|------|------|
| `EnsureAsync(Stream, needed, CT)` | 确保缓冲区有足够可读数据，不足则从流中读取 |
| `Peek(count)` | 偷看前 N 字节（不消费，不移动读指针） |
| `Read(count)` | 读取指定长度字节（移动读指针） |
| `Skip(count)` | 跳过已读字节 |
| `Compact()` | 将已读数据展平到缓冲区起始位置 |

#### 粘包/半包处理流程

```
TCP 流: [帧1前半][帧1后半+帧2前][帧2后+帧3...]

RingBuffer 处理:
  1. EnsureAsync(12) → 读够帧头
  2. Peek(12) → 获取数据域长度 N
  3. EnsureAsync(12+N+4) → 等待完整帧到达
  4. Deserialize → 消费完整帧
  5. 循环处理下一帧
```

### 4.5 PartialFileTracker - 分片文件重组跟踪器

**文件**: `ZepCommon/PartialFileTracker.cs`

**用途**: 接收端按文件 ID 重组分片数据，支持乱序到达。

#### 分片数据格式

```
┌──────────────┬──────────┬──────────────┬──────────┬──────────┬──────────┐
│文件名长度(4B) │ 文件名    │ 文件总大小(8B)│ 偏移(8B) │ 片长(4B) │ 分片数据  │
│ fileNameLen  │fileName  │  fileSize    │chunkOffset│chunkLen │ chunkData│
└──────────────┴──────────┴──────────────┴──────────┴──────────┴──────────┘
```

#### 核心方法

| 方法 | 说明 |
|------|------|
| `HandleChunk(frame, ...)` | 处理一个分片帧，返回是否完成重组 |
| `BuildChunkData(fileName, totalSize, offset, data)` | 构建分片帧的 Data 域（静态方法） |
| `CleanupStale(timeout)` | 清理超时的重组上下文 |

#### 重组流程

```
分片1 (offset=0, len=4096)     ──┐
分片3 (offset=8192, len=4096)   ─┤  按 offset 写入
分片2 (offset=4096, len=4096)   ─┤  FileAssemblyContext._buffer
  ...                            ─┤
分片N (最后一片)                 ──┘
                                  │
                    检查 _receivedBytes >= _totalSize
                                  │
                          完成 → 返回完整文件数据
```

#### 完整生命周期流程

```
Start()
  │
  ▼
AcceptLoopAsync() ← 循环接受连接
  │
  ├── 1. AcceptTcpClientAsync() → 接受 TCP 连接
  │
  ├── 2. TLS 握手
  │      AuthenticateAsServerAsync(Tls12 | Tls13)
  │      证书: 自签名 (server-tls.pfx)
  │      首次运行自动生成证书
  │
  ├── 3. 创建 KepConversation，加入 _onlineClients
  │
  └── 4. Task.Run → HandleConversationAsync()
         │
         ├── 阶段1: 纯文本下发版本列表
         │   "v1.0.0\r\nv1.1.0\r\n...\r\n\r\n"
         │
         ├── 阶段2: 纯文本等待客户端选择版本
         │   ReadTextLineAsync() → "v2.0.0"
         │
         ├── 阶段3: 帧协议身份认证
         │   ReceiveFrameAsync() → AuthRequest
         │   反序列化 Identity → 调用 OnAuthentication 验证
         │   发送 AuthResponse (Success/Fail)
         │
         ├── 阶段4: 心跳超时监控 (后台Task)
         │   每 5 秒检查一次
         │   30 秒无活动 → 断开连接
         │
         └── 阶段5: 主消息循环
             │
             ├── HeartbeatPing → 回复 HeartbeatPong
             ├── TimeSyncRequest → 回复服务器时间戳
             ├── TempUpload → 回复温度确认
             ├── ParamResponse → 完成等待中的响应
             ├── ClientRequest → 触发 OnClientRequestReceived 事件
             ├── FileUpload → HandleFileUpload() 分片重组
             └── FileDownloadAck → 记录日志
```

#### TLS 证书管理

```csharp
private X509Certificate2 CreateTlsCertificate()
{
    // 1. 检查是否存在 server-tls.pfx
    // 2. 存在 → 直接加载
    // 3. 不存在 → 生成自签名证书
    //    - CN=TcpSecureDemo Server
    //    - RSA 2048 位
    //    - SHA256 签名
    //    - 有效期: 前后1天 ~ 后1年
    //    - 保存为 server-tls.pfx (密码: tls-cert-pwd)
}
```

#### 文件下发流程

```
SendFileToClientAsync(clientId, filePath):
  1. 读取文件全部内容
  2. 计算分片数 = ceil(totalSize / 4096)
  3. 循环发送:
     每片: BuildChunkData(fileName, totalSize, offset, chunkData)
     构建 FileDownload 帧 (Id=fileId)
     SendFrameAsync()
     每 10% 打印进度
  4. 等待客户端回复 FileDownloadAck
```

#### 文件上传处理

```
HandleFileUpload(conv, frame):
  1. _uploadTracker.HandleChunk(frame) → 解析分片、写入缓冲区
  2. 每 10% 打印进度
  3. 完成时:
     - 保存到 data/{clientId}/{fileName}
     - 发送 FileUploadAck 确认
```

### 5.2 KepConversation - 客户端会话

**文件**: `KepServerCore/KepConversation.cs`

#### 类结构

| 成员 | 类型 | 说明 |
|------|------|------|
| `Id` | `string` | 会话 ID（8位 GUID 截取） |
| `Client` | `TcpClient` | TCP 客户端连接 |
| `SslStream` | `SslStream` | TLS 加密流 |
| `ConnectCts` | `CancellationTokenSource` | 连接停止信号 |
| `Authenticated` | `bool` | 是否已认证 |
| `LastActivity` | `DateTime` | 最后活动时间（UTC） |
| `SN` | `string?` | 设备序列号 |
| `Token` | `string?` | 设备令牌 |
| `_writeLock` | `SemaphoreSlim` | 写锁（保护并发写入） |
| `_ring` | `RingBuffer` | 环形缓冲区（8192B） |
| `_pendingResponses` | `ConcurrentDictionary<uint, TCS<DataPack>>` | 等待响应表 |

#### 核心方法

| 方法 | 说明 |
|------|------|
| `SendFrameAsync(frame, ct)` | 线程安全发送帧 |
| `ReceiveFrameAsync(ct)` | 接收帧（基于 RingBuffer） |
| `SendCommandAsync(paramData, timeoutMs, ct)` | 下发参数并等待回复（请求-响应模式） |
| `TryCompleteResponse(response)` | 完成等待中的响应 |
| `ReadTextLineAsync(ct)` | 纯文本阶段读取一行（\r\n 结束） |
| `WriteTextAsync(text, ct)` | 纯文本阶段发送文本 |

#### SendCommandAsync 请求-响应实现

```
1. 生成自增 reqId
2. 创建 TaskCompletionSource<DataPack>
3. 注册到 _pendingResponses[reqId]
4. 发送 ParamRequest 帧 (Id=reqId)
5. 创建超时 CancellationToken (默认10s)
6. await tcs.Task（阻塞等待）
7. finally: 从 _pendingResponses 移除

消息循环中收到 ParamResponse 时:
  → TryCompleteResponse() 匹配 Id
  → tcs.TrySetResult(response) → 解除阻塞
```

#### 连接流程详解

```
ConnectAsync(host, port, sn, token):
  │
  ├── 1. TCP 连接
  │      new TcpClient() → ConnectAsync(host, port)
  │      设置 NoDelay = true（禁用 Nagle 算法）
  │
  ├── 2. TLS 握手
  │      new SslStream(netStream, false, ValidateServerCertificate)
  │      AuthenticateAsClientAsync("localhost", Tls13)
  │      证书验证: 比对 SHA1 指纹
  │      ServerCertThumbprint = "1AAE881434ADAE1948738F343F179F0A6859FB5A"
  │
  ├── 3. NegotiateVersionAsync()
  │      逐字节读取直到 \r\n\r\n
  │      解析版本列表
  │      选择最后一个版本发送
  │
  ├── 4. AuthenticateAsync(sn, token)
  │      构建 Identity JSON
  │      发送 AuthRequest 帧
  │      接收 AuthResponse 帧
  │      检查 Success
  │
  ├── 5. Task.Run → ReadLoopAsync()（后台接收循环）
  │
  └── 6. Task.Run → HeartbeatLoopAsync()（后台心跳循环）
```

#### ReadLoopAsync 消息分发

```
ReadLoopAsync():
  while (!cancelled):
    frame = DataPack.ReceiveAsync()
    
    switch (FunctionCode):
      HeartbeatPong    → 计算 RTT 并记录日志
      TimeSyncResponse → 解析服务器时间，计算偏差
      TempAck          → 记录温度确认
      ParamRequest     → 触发 OnParamReceived
                         自动回复 ACK:{参数}
      ClientResponse   → TryCompleteResponse() 完成等待
      FileDownload     → HandleFileDownload() 分片重组
      FileUploadAck    → 记录上传确认
    
    OnFrameReceived?.Invoke(frame)  // 通知 UI 层
```

#### 异常处理策略

| 异常类型 | 处理方式 |
|----------|----------|
| `OperationCanceledException` | 正常取消，静默处理 |
| `EndOfStreamException` | 服务端断开连接，触发 OnDisconnect |
| `IOException (ConnectionReset)` | 服务端强制断开 RST，触发 OnDisconnect，日志提示重连 |
| `IOException (其他)` | 其他 IO 异常，触发 OnDisconnect |
| `Exception (通用)` | 记录异常信息，触发 OnDisconnect |

#### 心跳机制

```
HeartbeatLoopAsync():
  间隔: 10 秒
  条件: IsAuthenticated == true && !cancelled
  
  发送: HeartbeatPing (Data=当前时间戳ms)
  收到: HeartbeatPong (Data=服务端回显时间戳)
  计算: RTT = 当前时间 - 发送时间戳

服务端超时检测:
  每 5 秒检查 LastActivity
  30 秒无活动 → 断开连接
```

#### SendRequestAndWaitAsync 实现

```
1. reqId = Interlocked.Increment(ref _nextRequestId)  // 线程安全自增
2. tcs = new TaskCompletionSource<DataPack>()
3. _pendingResponses[reqId] = tcs
4. 发送 ClientRequest 帧 (Id=reqId, Data=requestData)
5. 创建超时 CancellationToken (默认10s)
6. 注册超时回调: tcs.TrySetException(TimeoutException)
7. await tcs.Task

ReadLoopAsync 收到 ClientResponse 时:
  → TryCompleteResponse() 匹配 Id
  → tcs.TrySetResult(response) → 解除阻塞
8. finally: 从 _pendingResponses 移除
```

## 十二、关键设计模式

### 12.1 请求-响应模式（异步等待）

```
发送方:                          接收方:
  reqId = GenerateRequestId()     
  tcs = new TCS<DataPack>()       
  _pending[reqId] = tcs           
  Send(Request, Id=reqId) ──────► Receive(Request)
  await tcs.Task (阻塞)           处理请求...
                                  Send(Response, Id=reqId) ──►
  Receive(Response) ◄──────────── 
  TryComplete(response)           
  tcs.SetResult(response)         
  → await 解除                    
```

### 12.2 环形缓冲区（粘包/半包处理）

```
场景: 一次 TCP Read 可能读到:
  - 不足一帧（半包）→ 继续等待
  - 恰好一帧 → 完美
  - 多帧粘连 → 逐帧解析

RingBuffer 策略:
  1. EnsureAsync(12) → 确保帧头完整
  2. Peek(12) → 获取数据长度 N
  3. EnsureAsync(12+N+4) → 确保完整帧
  4. Deserialize → 消费一帧
  5. 循环 → 处理下一帧
```

### 12.3 线程安全设计

| 组件 | 机制 | 说明 |
|------|------|------|
| `SemaphoreSlim _writeLock` | 互斥锁 | 保护 SslStream 并发写入 |
| `ConcurrentDictionary` | 无锁字典 | 在线客户端表、等待响应表 |
| `Interlocked.Increment` | 原子操作 | 自增请求 ID |
| `TaskCompletionSource` | 异步等待 | 请求-响应配对 |
| `CancellationTokenSource` | 取消令牌 | 连接生命周期管理 |
| `lock (_lock)` | 互斥锁 | FileAssemblyContext 分片写入 |
